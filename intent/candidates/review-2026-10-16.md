# Supervisor review of the three candidate intents, 2026-10-16

Three read-only Codex jobs (candidate-pr-evidence-d1, candidate-fleet-audit-d1,
candidate-skill-contract-d1) ran in parallel for four to five minutes each, rc 0, Codex weekly
window at 5 percent after them. Their outputs are copied verbatim into this directory as
pr-evidence.md, fleet-audit.md and skill-contract.md. This note is my reading of each against
intent/README.md, my answers to the open questions each draft asked, and the spike I am
dispatching for each. The decision is day 3; nothing here is it.

## What the drafts settled

pr-evidence: the draft inspected the wrapper and the ledger and showed the gap precisely. A jq
pass over the six completed ledger lines found no `branch`, `head_before` or `head_after` field in
any of them, and the wrapper computes a base SHA for its diff stat but never persists it. So the
receipt the candidate needs does not exist yet, which means the lab cannot test an exact join on
historical jobs; only on jobs run after the wrapper gains the receipt. The GraphQL probe could not
reach api.github.com from the read-only sandbox, so the review-round definitions are from the
GitHub documentation, not from a live query. The proposed definitions (a round is a distinct
reviewed head SHA; autonomy is attested, human-involved or unknown; first-attempt CI is attempt 1
of the earliest run per head) are usable from day one and are better than what docs/metrics.md
says today. The draft's own case against is the strongest of the three: this may be lab
instrumentation with a library interface, not a product.

Fleet Audit: the draft ran the commands the landscape review said were missing. `launchctl list`
returned exit 1 with no output in the sandbox while `launchctl print gui/501/<label>` worked and
exposed path, state, program, argv, working directory, runs, pid, last exit code and the interval
or calendar descriptor. It also found three cases a naive observer would get wrong: a disabled
override for a service that is no longer present (yabai), a loaded calendar job with no pid
(docker-restart), and an exit code with trailing text (`78: EX_CONFIG` on skhd). `crontab -l` was
denied by the sandbox. So the observer is feasible on this host and the output is text to parse,
not JSON. Not settled: whether the parse is stable enough to fixture, and how many of the dozen
services on the host parse fully.

Skill Contract Check: the draft inventoried three real skills (tts, dbt, playwright-cli) and was
honest that its only findings were sandbox artifacts: two commands absent from the research
PATH and a help command that exited 0 after a heredoc failed because the sandbox denied a temp
file. Its own judgement is that static checks belong in agentlint and the only defensible new
piece is the probe runner with identity-bound receipts. Not settled: whether a probe ever catches
something a static linter and an ordinary helper test would not.

## My leaning before the spikes

Fleet Audit first, pr-evidence second, Skill Contract Check third. Fleet Audit has a user with a
dozen jobs on the host and the riskiest part (parsing launchctl) was shown feasible today.
pr-evidence serves the lab directly, but the lab will instrument its wrapper either way, and a
candidate whose nearest neighbour is the lab's own bin/metrics risks being bookkeeping dressed
as a product. Skill Contract Check has not yet produced a finding that was not a sandbox
artifact. The spikes are meant to move these, not confirm them.

## Spikes dispatched

One short Codex job per candidate, workspace-write in a throwaway worktree on a `spike/<slug>`
branch that is never pushed or merged; the final message is copied into this directory as
spike-<slug>.md. Each has a proving command and a question it must answer yes or no.

- spike-pr-evidence: prototype the join over the seven-fixture matrix from the draft and capture
  a real receipt from its own run (branch, HEAD before and after, status before and after).
  Question: does an exact join survive a simulated squash with zero false exact links.
- spike-fleet-audit: parse real `launchctl print` output for every service in gui/501 into
  structured records and freeze five of them as fixtures. Question: how many of the host's
  services parse with pid, state, exit code, argv, working directory and schedule, and which fail.
- spike-skill-contract: a contract and probe runner for the installed tts skill, plus fixture CLIs
  that remove a flag, return empty output with exit 0, and change bytes without changing their
  version string. Question: does any probe fail on the real skill, and does the receipt catch the
  byte change that the version string misses.
